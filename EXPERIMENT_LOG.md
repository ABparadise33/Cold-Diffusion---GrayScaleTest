## 2026-09-04 — Official colorization fidelity and training-budget audit

- Question: user challenges whether our raw-like partial-color outputs and sepia full-gray outputs reflect differences from original Cold Diffusion, and correctly identifies data/training insufficiency as another unresolved explanation. Read-only diagnosis of model/operator/training; no model/config changes, checkpoint reuse, training, or push.
- Versions/sources: custom repository HEAD `4049d5f2066729d0eb1d83bb9e0f2b2ec487623f`; official repository `arpitbansal297/Cold-Diffusion-Models` commit `f8b1379151ff0cccba49112cf61d439bd4dd4ad9`, specifically `decolor-diffusion/`. Supplied `/Users/ed/Downloads/ColdDiffusion.pdf` is arXiv v1; converted with configured markitdown and visually read Appendix A.4 / Table 6 / Figure 14 on PDF pages 14–16. Do not silently equate this PDF version with the final conference paper or the current repository.
- Source-confirmed forward operator: original RGB decolorization composes 1x1 three-channel mixing kernels; with Linear + total removal, D(x,s) = (1-s/T)x + (s/T)P(x), where P is the per-pixel arithmetic RGB-channel mean. Our factor-1 natural RGB training input matches this operator (source equals target), modulo floating-point arithmetic. Our Lab interpolation to fixed `(L_raw,0,0)` is a custom conditional bridge, not this RGB operator. Official `to_lab` also converts to RGB before applying these kernels: it is not our direct Lab interpolation. Saturation factors greater than 1 add target edits/clipping and require a separate comparison; the factor-1 equivalence does not establish equivalence there.
- Confirmed reverse-operator difference: the paper and official RGB source re-degrade the predicted image itself, so their grayscale is P(pred). Our `bridge.py` and `diagnostics.sample_from_step` interpolate every prediction against fixed P(raw), and clamp each updated state to [-1,1]; the inspected official RGB sampler has no such per-step clamp. For a correctly indexed linear paper step, the increment is `(pred-P(pred))/T`; ours before clipping is `(pred-P(raw))/T`. These coincide only when the candidate's channel mean equals the raw anchor. The original RGB operator preserves each pixel's arithmetic channel mean (not CIE L*); our bridge can change it. This is a real algorithmic difference, not evidence that it alone causes brown hues. Historical Direct predictions are already sepia, before iteration, so a sampler-only explanation is insufficient.
- Official source indexing caveat: `q_sample` labels cumulative degradation after s applications with t=s-1. `sample`/`all_sample` pass T-1 down to 0, but `sample_one_step` applies `range(t.max())` kernels, and at t=0 returns the state unchanged. An actual extracted-method CPU test with a constant prediction counts 20 model calls but 19 nonzero updates for T=20. The paper's mathematical Algorithm 2 specifies 20 updates. Any reproduction must explicitly distinguish literal official-code behavior from a paper-index-correct variant; do not silently change it or claim the current official implementation is exactly the formula. This caveat does not remove the fixed-anchor mismatch above.
- Architecture: official default `train.py --model UnetConvNext` builds dim=64, multipliers (1,2,4,8), ConvNeXt blocks with linear attention. Instantiating that source gives 56,615,708 restoration-network parameters. Our base32 `RestorationUNet`, same multipliers but custom GroupNorm residual blocks and no attention, has 7,861,731 parameters (about 7.20x fewer). This is a comparison to the current official default architecture, not a claim to have verified the exact historical trained paper weights.
- Training/data: supplied Appendix A.4 reports 700,000 optimizer steps, Adam 2e-5, batch32 with accumulation2; official code confirms 700k and effective64 for CIFAR10, but uses batch16 x2 at >64px (CelebA128), so do not generalize effective64 to every repository experiment. CIFAR comparison therefore has 14x optimizer updates and 56x sampled-image presentations (44.8M vs 0.8M); these are not wall-clock/FLOP ratios. Official CIFAR10 uses its 50,000-image train split (https://cave.cs.toronto.edu/kriz/cifar.html); DIV2K has 800 HR train images with random128 crops. The 62.5x source-image-count difference is not a 62.5x independent-patch or information measure. Resolution, scene diversity, context and domain differ.
